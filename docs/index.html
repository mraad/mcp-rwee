2. System description

The client generates Python code. The client sends the code to the server. The worker runs the code on the Windows machine. The client gets the printed output and answers the question from it.

The system has two processes on the Windows machine. This is the main design decision. The server holds the network connection. The worker holds arcpy and the generated code.

2.1 Python environment

The worker must import arcpy. You cannot install arcpy with uv. For this reason, the uv environment uses the ArcGIS Pro Python as its base, and it can see the ArcGIS Pro packages.

2.2 Related approach: Code Mode

Philipp Schmid describes a related approach in Why Agents Are Soon Only Going to Have 1 Tool (1 November 2026). The name of the approach is Code Mode, or Programmatic Tool Calling. The model writes a script, and the script does the steps of the task. Only the data that the script returns goes into the context of the model.

This server uses the same principle. A script can read thousands of features, and the client gets only the printed output. The table shows the differences.

ItemCode Mode in the articlemcp-rwee
Tools that the model seesOne tool: exec(code)Four tools: read, write, edit, execute
What the script callsOther tools, through a typed bridgearcpy and Python libraries, directly
Data that goes to the modelData that the script returns through helpers such as text()Printed output, last 100,000 bytes
State between runsstore() and load()Files on disk and loaded imports. See section 5.2.
Where the script runsAn isolated sandboxThe worker, with the rights of the server's Windows user. It is not a sandbox. See section 12.

3. Tool reference

The server has four tools and one MCP prompt. Each path can be absolute. A relative path starts from the workdir.

3.1 read(path, offset=0, limit=None)

This tool returns UTF-8 text from a file. offset is the first line, and the first line of the file is 0. limit is the number of lines. If the file is not UTF-8 text, the tool returns an error.

For a non-negative line range, the tool stops reading after the requested lines. It does not check the rest of the file for UTF-8 errors. Negative values use Python slice rules and require reading the whole file.

3.2 write(path, content)

This tool makes or replaces a text file. It also makes the parent folders. It writes a temp file first, and then it replaces the target. If the write fails, the original file does not change.

3.3 edit(path, old_string, new_string, replace_all=False)

This tool replaces an exact string. The string must match one time, unless replace_all is true. If the string has no match or too many matches, the tool returns an error and the file does not change. Line endings do not change.

3.4 execute(target, args=None, timeout=300)

This tool runs code. The value of target selects how the code runs. The value of timeout must be finite and greater than 0.

If target isThe code runs inImportsargs
An existing .py fileThe workerStay loaded between runsAllowed
Any other valueA new shell processLoad on each runNot allowed

The result has these fields.

FieldMeaning
exit_codeThe exit code of the script or shell command. After a timeout, this value is null.
stdoutThe printed output. The tool keeps the last 100,000 bytes.
stderrThe error output. The tool keeps the last 100,000 bytes. After a crash, it also has the Python stack.
timed_outTrue if the code ran longer than timeout seconds.
crashedTrue if the script crashed the worker.
artifactsOne item for each file in the run folder. See section 3.6. If the run wrote no file, this list is empty.

If the client disconnects during execution, the server stops the worker or shell process and its child processes.

3.5 Prompt task(question)

This MCP prompt returns the text of the prompt file, and then the question. See section 8.

The prompt has 100 arguments: question, and w2 to w100. Only question is required. Claude Code 2.1.319 splits the text of the command at each space and gives one word to each argument. It drops words that have no argument. The server joins the arguments again with one space between words. A client that sends the full question in question needs no other arguments.

NOTE

Line breaks and repeated spaces in a question typed in Claude Code do not get to the server. If a question has more than 100 words, the server gets the first 100 words only, and the text after the question says that it may be cut off.

3.6 Artifacts

Each execute call gets its own run folder. The environment variable RWEE_ARTIFACT_DIR holds its path, in the worker and in a shell command. This applies to code in any language. To run TypeScript, use a shell command such as node my_script.mts.

Each item in artifacts has these fields.

FieldMeaning
uriThe resource address, artifact://<run>/<name>.
nameThe path of the file in the run folder.
sizeThe size in bytes.
sha256The SHA-256 value of the file. It is null if another process holds the file open.
mime_typeThe media type of the file.
download_pathThe path for an HTTP download. Add it to the server address that the client uses.

The client can get an artifact in two ways.

MethodFile sizeUse
MCP resource12,000,000 bytes or lessRead uri with the resource tool of the client. Claude Code saves the file with a .bin name, so copy it to the correct name.
HTTP downloadAny sizeDo an HTTP GET of download_path with the token. In a folder that remote.sh registered, use ./remote.sh fetch. See section 7.12.

MCP resources can only list and read artifacts. The tools write and edit refuse a path in --artifact-dir. A run that has not ended does not show its files. If timed_out or crashed is true, an artifact can be incomplete.

The server has two HTTP routes for artifacts. Each route needs the token.

RouteResult
GET /artifacts/<run>/<name>The file. The route accepts a Range header.
POST /artifacts/cleanupDeletes the run folders that are older than --artifact-ttl, and returns the number that it deleted. Newer folders stay.

The server also does this cleanup when it starts, and then every 5 minutes or after the value of --artifact-ttl, whichever is shorter. It deletes only folders that have a run id as a name, so other files in --artifact-dir stay. Windows does not delete a file that a process holds open. The next cleanup tries again.

CAUTION

Get an artifact soon after the run. The server deletes it after --artifact-ttl. Do not keep data in this folder that must stay.

5. How execute protects the server

A Python try statement cannot stop a crash in native code. Only a process boundary can stop it. For this reason, scripts run in the worker and not in the server.

The server does not start a new process for each script. The worker stays alive between scripts. This keeps arcpy imported. On the test machine, the first run took 4.51 seconds and the next run took 0.02 seconds.

5.2 What stays between runs

The worker keeps some state between scripts, and it resets other state.

ItemAfter a script ends
Library imports, such as arcpyStay loaded
arcpy.env valuesStay. Each script must set them.
in_memory dataStays and uses memory. arcpy.management.Delete("in_memory") removes it. On the test machine, each run of 200,000 points added about 26 MB.
Workspace .lock filesStay. arcpy.management.ClearWorkspaceCache() removes them.
Your helper modules in the script folder or workdirRemoved from memory, so an edit takes effect
Script globalsRemoved
sys.argv, sys.path, current folder, sys.stdout, sys.stderrSet back to the values before the script

To get a clean worker, run a script that contains import os; os._exit(0). The result shows crashed as true, and this is normal for this script. The next script starts a new worker.

5.3 Output capture

The worker connects its output streams to temp files at the operating system level. For this reason, it captures output from Python, from native code and from child processes. Large output cannot fill server memory, because the server reads only the end of each file.

6. Install procedure

Do these steps on the Windows machine. Use Command Prompt.

CAUTION

Install on a local disk. Do not use a shared folder such as \\Mac\Home for the .venv folder. This test used C:\Users\<user>\mcp-rwee.

6.1 Requirements

  • ArcGIS Pro, with a license for the Windows user that runs the server.
  • uv.
  • A copy of this repository.
  • OpenSSL on any machine, to make a TLS certificate. Git for Windows includes it.

6.2 Procedure

  1. Open Command Prompt as the user that will run the server.
  2. Go to the project folder. 
    cd /d C:\path\to\mcp-rwee
  3. Make the environment from the ArcGIS Pro Python. 
    uv venv --python "C:\Program Files\ArcGIS\Pro\bin\Python\envs\arcgispro-py3\python.exe" --system-site-packages
  4. Install the packages. 
    uv sync
  5. Make the empty conda-meta folder. 
    mkdir .venv\conda-meta
  6. Test the imports. 
    .venv\Scripts\python.exe -c "import arcpy, numpy, pandas; print(arcpy.GetInstallInfo()['Version'], arcpy.ProductInfo())"
  7. Make sure that the output shows your ArcGIS Pro version and license level. On the test machine, the output was 3.7.3 ArcInfo.
  8. Run the tests. 
    .venv\Scripts\python.exe -m pytest -q
  9. Make sure that all tests pass.
NOTE

Without conda-meta, arcpy prints a warning about Conda when it loads. The arcpy check looks only for this folder name. The command uv venv --clear removes the folder, so do step 5 again after that command.

6.3 Alternative procedure

Use this procedure only if the import test in step 6 fails. This alternative is not tested.

  1. Clone the ArcGIS Pro environment. 
    conda create --clone arcgispro-py3 --name rwee
  2. Install the packages in the clone. 
    uv pip install --python "<clone folder>\python.exe" -r pyproject.toml
  3. Use <clone folder>\python.exe to start the server in section 7.

7. Start, connect and stop

7.1 Set the prompt file

  1. Open prompts\arcpy.md in a text editor.
  2. Go to the "Machine details" section.
  3. Replace the example interpreter path with your path.
  4. Replace the example data folder with your data folder.
  5. Save the file.

7.2 Start the server

  1. Make a token. 
    .venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
  2. Set the token. The server does not start without it, or with fewer than 32 characters. 
    set MCP_RWEE_TOKEN=<the value from step 1>
  3. Make a TLS certificate and key. Replace the address with the address that the client uses. For a host name, use DNS:<name>. 
    openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem -out cert.pem -days 365 -subj "/CN=rwee" -addext "subjectAltName=IP:10.211.55.4"
  4. Put cert.pem and key.pem in a folder on the Windows machine that only the server user can read.
  5. Copy cert.pem to the client machine. Do not copy key.pem.
  6. Start the server. 
    .venv\Scripts\python.exe server.py --prompt prompts\arcpy.md --workdir C:\work --host 0.0.0.0 --port 8765 --ssl-certfile C:\certs\cert.pem --ssl-keyfile C:\certs\key.pem
WARNING

Do not disable TLS for a direct remote connection. Without TLS, a person who can see the network traffic can read the token. The server does not start with a non-local --host and no certificate. An SSH tunnel encrypts the traffic, so section 7.7 does not use a certificate.

OptionDefaultPurpose
--artifact-dirThe folder mcp-rwee-artifacts-<port> in the system temp folderThe folder for run folders. It must not contain the workdir. A server lists all finished runs in this folder, so give each server its own folder. See section 3.6.
--artifact-ttl24hThe time to keep a run folder after the run ends. Use a number and the unit s, m, h or d, for example 90m.
--promptNone. You must set it.The prompt file.
--workdirCurrent folderThe start folder for relative paths and for code that runs.
--host127.0.0.1The address to listen on. Any address that is not local needs a certificate. Use 127.0.0.1 if a client is on the same machine or a tunnel on the same machine forwards to the server.
--port8000The port.
--ssl-certfileNoneThe TLS certificate file, in PEM format.
--ssl-keyfileNoneThe TLS private key file, in PEM format. Set this option and --ssl-certfile together.

If the Windows Firewall blocks the port, do the procedure in section 7.8. The first test machine already allowed Python, so its TLS test did not need a rule. Section 7.7 gives an SSH tunnel, which needs no certificate and no firewall rule. A reverse proxy can also give TLS. In that case, use --host 127.0.0.1. The reverse proxy is not tested.

7.3 Connect a Claude Code client

  1. On the client machine, make a file with the name mcp.json.
  2. Put this text in the file. Replace the host and the token. 
    {"mcpServers": {"rwee": {"type": "http",
  "url": "https://<host>:8765/mcp",
  "headers": {"Authorization": "Bearer <token>"}}}}
  3. Start Claude Code with this file. Set NODE_EXTRA_CA_CERTS to the full path of cert.pem, so that the client trusts the certificate. 
    NODE_EXTRA_CA_CERTS=/full/path/cert.pem claude --mcp-config mcp.json
  4. Make sure that the four tools appear as mcp__rwee__read, mcp__rwee__write, mcp__rwee__edit and mcp__rwee__execute.

7.4 Do the smoke test

Do this test on each new Windows machine. Tell the client to do these steps with the MCP tools.

  1. Write this script as smoke.py. 
    import time
start = time.time()
import arcpy, numpy, pandas
print(arcpy.GetInstallInfo()["Version"], arcpy.ProductInfo(), round(time.time() - start, 2))
  2. Execute smoke.py.
  3. Execute smoke.py again.
  4. Make sure that the second time is much smaller than the first time.
  5. Make sure that stderr is empty.
  6. Write import faulthandler; faulthandler._sigsegv() as crash.py.
  7. Execute crash.py.
  8. Make sure that crashed is true.
  9. Execute smoke.py.
  10. Make sure that it runs without error.
  11. Write import time; time.sleep(60) as slow.py.
  12. Execute slow.py with timeout set to 2.
  13. Make sure that timed_out is true.

7.5 Stop the server

  1. Find the process number of the server. It is the last value on the line. 
    netstat -ano | findstr LISTENING | findstr :8765
  2. Stop the process and its child processes. 
    taskkill /F /T /PID <process number>
CAUTION

If you start the server in an SSH session, closing that session did not stop the server in the test. The server continued to listen, and its token continued to work. Always do this procedure, and then make sure that the netstat command shows no line.

NOTE

The process on the port is the server. Its parent process is the launcher. Steps 1 and 2 in section 15.12 find both. In that test, taskkill /F /T on the launcher stopped the launcher, the server, the worker and a child process of the worker.

7.6 Set up SSH on the Windows machine

Do this procedure one time. The SSH tunnel in section 7.7 needs it.

  1. On the Windows machine, open PowerShell as an administrator.
  2. Install OpenSSH Server. 
    Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
  3. Start the service. 
    Start-Service sshd
  4. Set the service to start automatically. 
    Set-Service sshd -StartupType Automatic
  5. Show the fingerprint of the host key. 
    ssh-keygen -lf C:\ProgramData\ssh\ssh_host_ed25519_key.pub
  6. Record the fingerprint.
  7. On the client, copy your public key to the Windows machine. Replace <user> with the Windows login name. Replace id_rsa.pub with the name of your public key. If you have no key, first make one with ssh-keygen -t ed25519. SSH uses only the default key names, such as id_rsa and id_ed25519, unless your SSH configuration gives a different name. 
    scp ~/.ssh/id_rsa.pub <user>@<host>:key.pub
  8. Compare the fingerprint that scp shows with the fingerprint that you recorded.
  9. Answer yes only if the two fingerprints are the same.
  10. Type the Windows password.
  11. On the Windows machine, add the key to the key file for administrators. 
    Get-Content $HOME\key.pub | Add-Content -Encoding ascii C:\ProgramData\ssh\administrators_authorized_keys
  12. Set the permissions of the key file. 
    icacls C:\ProgramData\ssh\administrators_authorized_keys /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"
  13. Delete the copy of the key. 
    Remove-Item $HOME\key.pub
  14. On the client, test the connection. 
    ssh <user>@<host> hostname
  15. Make sure that the machine name appears and that SSH does not ask for a password.
WARNING

If the fingerprints are not the same, do not connect. A different machine can be answering with this name.

NOTE

Windows does not use the key file of the user for a member of the Administrators group. For a user that is not an administrator, put the key in C:\Users\<user>\.ssh\authorized_keys, and do not do the icacls step. To see the members of the group, use net localgroup Administrators. The test used only the key file for administrators.

7.7 Connect through an SSH tunnel

Use this procedure if the client can connect to the Windows machine with SSH. It needs no certificate and no firewall rule for the server port. Do section 7.6 first.

  1. Make a token and set it. Do steps 1 and 2 in section 7.2.
  2. Start the server on the local address of the Windows machine. Do not set a certificate. 
    .venv\Scripts\python.exe server.py --prompt prompts\arcpy.md --workdir C:\work --host 127.0.0.1 --port 8765
  3. On the client, open the tunnel. Keep this window open. 
    ssh -o ExitOnForwardFailure=yes -N -L 127.0.0.1:8765:127.0.0.1:8765 <user>@<host>
  4. On the client, make a file with the name mcp.json. Put this text in the file. The client reads the token from the environment, so the token is not in the file. 
    {"mcpServers": {"rwee": {"type": "http",
  "url": "http://127.0.0.1:8765/mcp",
  "headers": {"Authorization": "Bearer ${MCP_RWEE_TOKEN}"}}}}
  5. Start Claude Code with the token and this file. 
    MCP_RWEE_TOKEN=<token> claude --mcp-config mcp.json
  6. Make sure that the four tools appear.
  7. When you finish, close the tunnel.
  8. Stop the server. Do section 7.5.
CAUTION

Keep 127.0.0.1 at the start of the -L value, and do not use ssh -g. A different address or -g can let other machines connect to the tunnel port. Other users of the client machine can connect to this port, so the token is still necessary.

Keep ExitOnForwardFailure=yes. Without it, SSH can stay open with no tunnel if a different process uses the port. The client then sends the token to that process.

NOTE

If the tunnel closes during a script, the server stops that script. Open the tunnel again, connect again and run the script again. The server does not need a restart.

7.8 Open the firewall for a direct connection

Use this procedure only for a direct connection with TLS. This procedure is not tested on a machine that blocks the port.

  1. Make the token and the certificate. Do steps 1 to 5 in section 7.2.
  2. On the Windows machine, open PowerShell as an administrator.
  3. Add a rule for the client address only. 
    New-NetFirewallRule -DisplayName "mcp-rwee" -Direction Inbound -Protocol TCP -LocalPort 8765 -RemoteAddress <client address> -Action Allow
  4. Start the server. Do step 6 in section 7.2.
  5. Connect the client. Do section 7.3.
  6. When you no longer need the connection, stop the server. Do section 7.5.
  7. Remove the rule. 
    Remove-NetFirewallRule -DisplayName "mcp-rwee"
NOTE

If the address of the client changes, the rule stops the connection. Change the rule. On a domain machine, a domain policy can ignore local firewall rules. If this occurs, speak to the domain administrator, or use section 7.7.

7.9 Let Claude Code start the server

This section applies only if a Claude Code session starts the server for you. The Claude Code permission system can stop this command, and it is separate from the Windows Firewall.

In the test, the permission system stopped a command that started the server with --host 0.0.0.0. It gave no reason. Later, after the user asked for a tunnel, it allowed a command that started the server with --host 127.0.0.1. Do not expect the same result each time.

You can use one of these two methods:

  • Start the server yourself. This method needs no permission change. Tell the session when the server is running.
  • Add a permission rule to .claude/settings.local.json. This rule is not tested. 
    { "permissions": { "allow": ["Bash(ssh -o BatchMode=yes <host>:*)"] } }
WARNING

This rule lets the session run any command on the Windows machine without a request for approval. Start the server yourself if you do not need this access.

7.10 Start the server from the client

Use this procedure to start the server over SSH, with no work in a window on the Windows machine. The script in section 7.12 does this procedure and section 7.11 with one command. Do section 6 and section 7.6 first. The commands are for a Mac or Linux client. The test used a name from the SSH configuration, in place of <user>@<host>.

  1. Set new files so that only you can read them. 
    umask 077
  2. Make a token in a file. 
    python3 -c "import secrets; print(secrets.token_urlsafe(32))" > rwee.token
  3. Make the workdir on the Windows machine. 
    ssh <user>@<host> "if not exist C:\work mkdir C:\work"
  4. Copy prompts/arcpy.md to a new file with the name arcpy-prompt.md. 
    cp prompts/arcpy.md arcpy-prompt.md
  5. Set the "Machine details" section in the new file.
  6. Copy the new file to the Windows machine. 
    scp arcpy-prompt.md <user>@<host>:C:/work/arcpy-prompt.md
  7. Copy the token file to the Windows machine. 
    scp rwee.token <user>@<host>:C:/work/.rwee-token
  8. In a second window, start the server. Keep this window open. set /p reads the token from the file, so the token is not in the command. 
    ssh <user>@<host> "cd /d C:\Users\<user>\mcp-rwee && set /p MCP_RWEE_TOKEN=<C:\work\.rwee-token && .venv\Scripts\python.exe server.py --prompt C:\work\arcpy-prompt.md --workdir C:\work --port 8765"
  9. In a third window, open the tunnel. Keep this window open. 
    ssh -o ExitOnForwardFailure=yes -N -L 127.0.0.1:8765:127.0.0.1:8765 <user>@<host>
  10. In the first window, send a request with no token. 
    curl -s -o /dev/null -w '%{http_code}\n' -X POST http://127.0.0.1:8765/mcp
  11. Make sure that the result is 401. If the result is different, wait for the server to start, and do step 10 again.
  12. Delete the token file on the Windows machine. 
    ssh <user>@<host> "del C:\work\.rwee-token"
  13. Connect the client. Do section 7.11, or do steps 4 to 6 in section 7.7.
CAUTION

The token is in a file on the Windows machine from step 7 to step 12. Do step 12 immediately after step 11. Closing the second window does not stop the server. To stop the server, do section 7.5.

7.11 Register the server in Claude Code

Use this procedure if you want Claude Code to connect to the server without --mcp-config. The tunnel in section 7.7 or section 7.10 must be open. Do this procedure in the folder that has rwee.token, or give the full path of that file.

  1. On the client, go to the folder that will use the server. The value local applies the registration to this folder only. 
    cd <project folder>
  2. Add the server. 
    claude mcp add --transport http --scope local rwee http://127.0.0.1:8765/mcp --header "Authorization: Bearer $(cat rwee.token)"
  3. Show the servers. 
    claude mcp list
  4. Make sure that the rwee line shows Connected.
  5. Start a new Claude Code session in this folder. A session that is already open does not get the new tools.
  6. When you finish, remove the registration. 
    claude mcp remove rwee -s local
  7. Delete the token file. 
    rm rwee.token
WARNING

Step 2 writes the token as plain text in ~/.claude.json. A person who can read this file and reach the port can run code on the Windows machine. To keep the token out of a file, use the mcp.json file in section 7.7.

NOTE

The first test did steps 1 to 4, then steps 6 and 7. A later test did step 5 and made tool calls in a new session, and the command /mcp__rwee__task gave the full question. After step 6, claude mcp list did not show rwee, and ~/.claude.json did not contain the token. A new token needs a new registration, so do step 6 and then step 2 again.

7.12 Use the script remote.sh

The script remote.sh does section 7.10 and section 7.11 with one command. One other command stops the server, closes the tunnel and removes the registration. The script runs on the client.

Do section 6 and section 7.6 first. The server install must be in %USERPROFILE%\mcp-rwee on the Windows machine. The client must have bash, ssh, scp, curl, openssl, iconv, base64 and claude. The command fetch also needs python3 and shasum.

8.1 Text of prompts/arcpy.md

# ArcPy execution environment

This server is based on ArcPy, on a remote Windows machine with ArcGIS Pro. Your job is to generate Python code with ArcPy, execute it on that machine, and answer from the results. Your code can also use NumPy, Pandas and the other libraries in this Python environment. Files and code exist on the remote machine, not on yours.

## Machine details

Edit this section for your machine.

- Interpreter: `C:\path\to\mcp-rwee\.venv\Scripts\python.exe`
- Data folders: `C:\path\to\data`

## How to answer a question

1. Generate a Python script that gets what the question needs.
2. Save it with `write`, and run it with `execute`.
3. If execution fails, use the traceback in `stderr`. Correct the script with `edit`, and run it again. Change the code on each retry.
4. If the output does not answer the question, change the script and run it again.
5. Answer from the output. Do not state a result that the output does not show.

## Rules for scripts

- Only printed output comes back. Output over 100,000 bytes is cut from the start, so print summaries of large results.
- Call `arcpy.ResetEnvironments()` and then set `arcpy.env.workspace` and other `arcpy.env` values at the top of each script. Values from an earlier run persist.
- Use `with` for cursors, or delete them. A cursor that stays open keeps its lock on the data.
- The worker keeps a `.lock` file on a workspace between runs. If another process must change that data, call `arcpy.management.ClearWorkspaceCache()` at the end of the script.
- `in_memory` data stays between runs and uses memory. Call `arcpy.management.Delete("in_memory")` when you no longer need it.
- `read` returns UTF-8 text only. Write a plot or other binary file to the artifact folder.
- Each run starts with new script globals.

## What `execute` does

An existing `.py` file runs in a long-lived Python worker. Installed modules such as `arcpy` stay imported between runs, so `arcpy` is fast after the first run. Helper modules in the script folder or workdir load again on each run, so do not keep state in them. Only one script runs at a time. If `execute` returns a "busy" error, wait and try again. To get a clean worker, run a script that contains `import os; os._exit(0)`. The result then shows `crashed` as true, and this is normal.

- `crashed` is true when the script stopped the worker. The server restarts it for the next run. `stderr` can hold the Python stack. A script exception does not set `crashed`: `exit_code` is 1, and `stderr` holds the traceback.
- `timed_out` is true when the script ran longer than `timeout` seconds (default 300). The worker restarts for the next run. Pass a larger `timeout` for long geoprocessing.

Any other `target` runs as a shell command in a new process. For `robocopy`, an exit code below 8 is not a failure. Use a shell command for a script that uses `multiprocessing`, with the interpreter above.

## Artifacts

Each run gets an empty folder in the environment variable `RWEE_ARTIFACT_DIR`, for any language. Run TypeScript as a shell command, for example `node my_script.mts`. `artifacts` in the result has one item for each file.

- For a file of 12,000,000 bytes or less, read the resource at `uri` with your MCP resource tool. Claude Code saves it with a `.bin` name, so copy it to the correct name.
- For a larger file, in a Claude Code session started with `remote.sh`, run `./remote.sh fetch <download_path> <local file>`. Otherwise, send `Authorization: Bearer <token>` with an HTTP GET to the server address and `download_path`.
- Compare the `sha256` value. After a timeout or crash, a file can be incomplete.

Artifacts are read-only. The server deletes them after a time, so get them soon.

11. Limits and items not tested

11.1 Limits

  • The worker runs one script at a time.
  • After a crash or a timeout, the next script loads arcpy again. This took about 4 seconds on the test machine.
  • The read tool returns only UTF-8 text. It cannot return an image. To get a binary file, use an artifact.
  • The read tool refuses a file over 12,000,000 bytes without a limit or with a negative offset. Read a large file in parts with a positive offset and a limit.
  • Claude Code 2.1.319 rejects a response over 16 MB. A resource read therefore has a limit of 12,000,000 bytes. A 12,500,000-byte read passed and a 50,000,000-byte read failed. A larger file needs the HTTP download.
  • In a one-shot Claude Code session (claude -p), ListMcpResourcesTool shows the list from the start of the session. It does not show an artifact from a later run in that session. A new session shows it. The server sends the list change, and an SDK client receives it. Use uri from the execute result, because a read does not need the list.
  • The list of resources has no pagination.
  • The artifact folder has no size limit. A run can fill the disk.
  • server.py uses the private FastMCP attribute _mcp_server to add subscriptions/listen, because FastMCP 4.1 does not serve this method. A new FastMCP version can change this attribute.
  • in_memory data uses memory until a script deletes it or the worker stops.
  • Output files have no size limit. A script that prints without end can fill the disk until its timeout.
  • A script that uses multiprocessing must run as a shell command. See section 8.
  • C library output that is still in a buffer when a script ends can appear in a later run.
  • If the server stops during a native call that holds the Python global lock, the worker stops only after that call returns. This was not seen in the tests.
  • The server has no Windows service setup. You must start it manually.
  • A Claude Code session reads its list of MCP servers when it starts. It does not get the tools of a server that you register later.
  • If remote.sh start cannot reach the host, the exit code is 255, from ssh. For remote.sh stop, the exit code is 1. A program that calls the script must look for an exit code that is not zero.
  • remote.sh uses the fixed workdir C:\work and the fixed prompt file C:\work\arcpy-prompt.md.

11.2 Items not tested

  • A reverse proxy. The TLS test used a self-signed certificate on the private Parallels network.
  • A proxy with a time limit on quiet connections. If it closes the connection during a long script, the server stops the worker. An SSH tunnel stayed open for a quiet period of 90 seconds, and a longer period is not tested.
  • A direct TLS connection between two physical machines. The test between physical machines used an SSH tunnel.
  • The firewall procedure in section 7.8, and the permission rule in section 7.9.
  • A claude.ai web connector. It expects OAuth, so it needs a different auth= value in server.py.
  • Libraries with compiled code in the workdir, but not in .venv. These libraries can fail on the second run, because the worker removes helper modules from memory.
  • A crash that arcpy itself causes. The test made the crash with faulthandler._sigsegv() after import arcpy.
  • A dedicated low-privilege Windows user, and its ArcGIS Pro license.
  • The alternative procedure in section 6.3.
  • remote.sh on a Linux client.
  • ListMcpResourcesTool in an interactive Claude Code session, after a run.
  • An HTTP download over a direct TLS connection. The tests used plain HTTP on the local machine and through an SSH tunnel.
  • These paths of remote.sh: a busy port on the client or on the Windows machine, a failure of claude mcp add, a server that does not answer 401, and the copy of the prompt file to a new machine.
  • All features of the arcgis package. The test only imported it. A package in .venv can replace an ArcGIS Pro version of the same package.

12. Security

WARNING

The execute tool runs any code that a client sends. A person who has the token can run code as the server's Windows user. Do not expose the port to a network that you do not trust.

WARNING

The token goes in each request. For remote access, use TLS. The server does not start with a non-local --host and no certificate. Keep key.pem secret, because a person who has it can impersonate the server.

WARNING

FastMCP does not check the token on an added HTTP route. A test route with no token check returned its file to a request with no token. The artifact routes check the token themselves. A new route must also do this.

CAUTION

Artifacts are read-only through MCP, but this is not a security boundary. Code that execute runs can change or delete them. A person who has the token can get any artifact until the server deletes it. On Windows, the default artifact folder is in the temp folder of the server's user.

CAUTION

The worker protects against a crash. It is not a security boundary. Generated code has the same rights as the server, so it can read and delete files of that user. Use a Windows user that has access only to the necessary data.

WARNING

Closing an SSH session did not stop a server that started in that session. A server that you forget continues to accept its token. Do section 7.5 or remote.sh stop when you finish, and make a new token for the next use. remote.sh start makes a new token each time.

WARNING

claude mcp add --header writes the token as plain text in ~/.claude.json. Remove the registration when you finish. See section 7.11. remote.sh start does this registration too, and remote.sh stop removes it. See section 7.12.

The server removes MCP_RWEE_TOKEN from the environment of the worker and of shell commands. This does not make the token secret from generated code, because code that runs as the same user can read the server process. The server does not start without a token of at least 32 characters. There is no mode without authentication.

The prompt file tells the client to run code until it finds what it needs. Each run can change data. Use a copy of important data. 15.7 The method

The script does these operations in this order. Section 15.13 gives the full script.

  1. Open the project with arcpy.mp.ArcGISProject.
  2. Get the data source of each layer.
  3. Close the project object. The script does not save the project.
  4. Make a temporary layer of wellbores with water_depth > 350.
  5. Make a temporary layer of pipelines with current_phase = 'IN SERVICE'.
  6. Do method 1: SelectLayerByLocation with WITHIN_A_DISTANCE_GEODESIC.
  7. Do method 2: GenerateNearTable with GEODESIC. Compare each distance with the limit.
  8. Do method 3: calculate the distance from each wellbore to each pipeline segment with NumPy.
  9. Compare the three sets of object IDs.
  10. Calculate the statistics with the Python statistics module.
  11. Calculate the statistics again with the Statistics tool.
  12. Delete the temporary layers and the memory tables.

Method 3 does not use an arcpy distance operation. It adds vertices to each pipeline with densify, at 1,000 m or less. It then uses a flat local scale at the latitude of each wellbore, on the International 1924 ellipsoid. This ellipsoid is the ellipsoid of ED50.

def distance_to_pipes(lon, lat):
    s = math.sin(math.radians(lat))
    w = math.sqrt(1 - E2 * s * s)
    my = math.radians(1) * A * (1 - E2) / w ** 3
    mx = math.radians(1) * A / w * math.cos(math.radians(lat))
    ax, ay = (seg[:, 0] - lon) * mx, (seg[:, 1] - lat) * my
    bx, by_ = (seg[:, 2] - lon) * mx, (seg[:, 3] - lat) * my
    dx, dy = bx - ax, by_ - ay
    t = np.clip(-(ax * dx + ay * dy) / np.maximum(dx * dx + dy * dy, 1e-9), 0, 1)
    return float(np.hypot(ax + t * dx, ay + t * dy).min())

This is the scripted MCP client on the Mac. It is not part of the project. Run it with uv run python rwee_call.py from the project folder, so that it can import FastMCP. It reads the token from rwee.token in its own folder.

"""Call one rwee MCP tool through the tunnel. Usage:
  rwee_call.py write REMOTE_PATH LOCAL_FILE
  rwee_call.py execute TARGET [TIMEOUT]
  rwee_call.py read REMOTE_PATH
"""
import asyncio
import pathlib
import sys

from fastmcp import Client
from fastmcp.client.auth import BearerAuth

TOKEN = (pathlib.Path(__file__).parent / "rwee.token").read_text().strip()


async def main(tool, rest):
    if tool == "write":
        args = {"path": rest[0], "content": pathlib.Path(rest[1]).read_text(encoding="utf-8")}
    elif tool == "execute":
        args = {"target": rest[0], "timeout": int(rest[1]) if len(rest) > 1 else 300}
    else:
        args = {"path": rest[0]}
    async with Client("http://127.0.0.1:8765/mcp", auth=BearerAuth(TOKEN), timeout=1800) as client:
        result = await client.call_tool(tool, args)
    data = result.data
    if isinstance(data, dict):
        for key, value in data.items():
            print(f"[{key}]\n{value}" if key in ("stdout", "stderr") else f"[{key}] {value}")
    else:
        print(data)


asyncio.run(main(sys.argv[1], sys.argv[2:]))
